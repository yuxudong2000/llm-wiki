# 应答设计：「它会不会把故障当成正常学进去？」

> 来源：一张应答话术设计示意图（原始图片未归档，仅整理文字内容）
> 整理时间：2026-09-23

> [!warning] 保密标记
> 原图页脚标注「[保密级] 仅限国内团队内部，不得外发 | 适用：D1『常被问 · 故障会不会被学进去』帧 | SCHEMATIC · 半径与轨迹为机制示意，非实测数据；例外① 的遥测仅在参考实现核实，出货端未核」。与前几张同属一份材料（承 [在线原型库.md](./在线原型库.md)、[神经形态芯片.md](./神经形态芯片.md)）。**本仓库会 push 到 git remote**，入库前需确认可达范围或做去标识化处理。

**一句话**：这一帧不是讲机制，是**教己方人员怎么回答客户最难的一个质疑**。核心手法是把一个听起来无解的质问（"你会不会把故障学成正常，然后就不报警了"）翻译成**几种可精确判定的几何状态**，再用分层应答把信息按需释放。

**顶部导语**：

> 这是这一行**最难**的问题，而且它是个**好问题**。三层答法：**层1指着左图讲，层3只在被追问时给**。

两个细节值得注意：

1. **"而且它是个好问题"**——不是公关式的"这个问题很好"然后回避。承认这个质疑命中了系统的真实软肋（结合右下角"例外②"，它确实命中了），值得认真拆解。
2. **"层3只在被追问时给"**——信息按需求深度释放，不是一上来倒完。这与 [竞品路线B-经典统计五件套.md](./竞品路线B-经典统计五件套.md) 的"一次只留一个记忆点"是同一套沟通设计。

## 一、层1：左图——两条出口 + 第三种状态

这是对 [在线原型库.md](./在线原型库.md) 里"两条出路"的**补完**：之前只讲了"匹配上 / 没见过"的二元分支，这一帧补上了**第三种、也是最关键的状态**。

虚线圆标注「**虚线 = 匹配半径**」，中心灰点 = 「**已有状态（原型）**」。

### ① 特征不像 → 直接报「没见过」

左上红点孤零零落在半径外 → 走之前讲过的那条路：连最像的原型都够不着，报「没见过」。

### ② 在发展 → 越预算 → 隔离

右上几个红点呈现出**渐进轨迹**（从圆内往外爬，箭头指向"越预算"）。

含义：新数据**持续、系统性地朝一个方向偏移**，且偏移速度**超过漂移预算** → 说明这不是"缓慢漂移可以跟"的范畴，系统**不再把它当正常样本吸收，而是隔离**。

这里的"预算"正对应 [在线原型库.md](./在线原型库.md) 「受约束的在线学习」三条限定里的**有预算上限**——那一篇只说了"更新幅度/频次/总量受控"，这一帧才显示预算耗尽在**几何上**长什么样：样本点走出匹配半径、且走出速度超限。

### ③ 既不像、也不增长 → 跟住它是正确行为

图下方文字（对应左图圆内那一小簇灰点）：

> **既不像、也不增长** —— 绝大多数确实不是故障而是漂移，**跟住它是正确行为，不是失职**。

这是回答问题的**核心论点**。客户的担忧是"学进去 = 纵容故障"，但实际分布是：

| 新样本的实际形态 | 系统判定 | 是否正确 |
|---|---|---|
| 远离原型、长期不趋近 | 报「没见过」 | ✅ 正确（交人核查） |
| 持续朝一个方向偏、速度超预算 | 隔离 | ✅ 正确（不接受为正常） |
| **既不像已知异常，又没有持续增长趋势** | **吸收进原型（跟住）** | ✅ **正确——这才是绝大多数** |

第三行是关键：客户脑子里想的是"任何偏离都可能是故障"，但真实世界里**绝大多数缓慢变化确实只是漂移**（传感器老化、季节温度、润滑劣化）。对这类样本，"跟住"才是对的行为；若一律拒绝吸收，系统会迅速积累误报而失去可用性。

**这一层完成的翻译**：客户问"会不会学进去"（一个听起来无法证伪的质疑）→ 回答把它拆成三种可判定的几何状态（半径外 / 越预算 / 半径内且不增长）。问题从"你的系统可不可信"变成"你的偏移轨迹落在哪一类"，**后者是可检验的**。

## 二、例外①（右上）：库到容量上限之后

这是全帧**信息密度最高的技术补丁**，补齐了 [在线原型库.md](./在线原型库.md) 里没有交代的架构细节。

### 2.1 两级结构（新信息）

> 不是「没有存储」—— 架构上有**两级**：**K 槽工作记忆 + N 条持久库**。

| 层级 | 图上说法 | 推断作用 |
|---|---|---|
| **K 槽工作记忆** | working memory | 短期缓冲，承接被"隔离"出来、尚未确认是否转正的候选模式 |
| **N 条持久库** | persistent library | 长期存活的原型库，即 [在线原型库.md](./在线原型库.md) 里讲的那套"典型状态原型" |

> [!warning] 命名冲突（整理时勿混）
> [在线原型库.md](./在线原型库.md) 用 **K** 表示**原型条数**；本帧用 **K** 表示**工作记忆槽位数**、**N** 表示持久库条数。**两帧对字母 K 的指代不同**，做变量对照时不能直接合并。本页约定：K=工作记忆槽数，N=持久库条数。

### 2.2 咬人的是 N 的容量上限

> 到顶之后，超限输入被**静默并入最近的一条（返回值同形）**。

展开这半句的技术含义：

- **静默**：不报错、不告警、不向调用方区分这一条是"独立原型"还是"被归并的"；
- **并入最近的一条**：新候选被强行塞进库里最接近的那条原型（可能连带的后果是那条原型被带偏，也可能只是丢弃候选）；
- **返回值同形**：从接口看，输出格式与正常匹配完全一致——**外部无法从返回值上区分"这是一条真正独立的原型"还是"这是被归并的结果"**。

这是"静默"一词真正的分量：它指的是**外部不可观测**，不是"系统内部没记录"。

### 2.3 "推后 ≠ 消除"

> **加大 N 能推后这个点 —— 端侧有界，推后≠消除。**

全帧最要紧的一句诚实表态，写法与前几篇同一族：

| 笔记 | 措辞纪律 |
|---|---|
| Mamba/SSM/LMU | 打平 ≠ 更准；CMAPSS 超 SOTA 是假的 |
| 神经形态芯片 | 可以映射 ≠ 更适合 |
| **本篇** | **推后 ≠ 消除** |

没有说"扩容能解决"。精确区分了两件事：扩大 N 只是把"库满"这个临界点**往后推**；但**端侧设备资源有界**，N 不可能无限扩，所以"库满导致静默归并"这个现象**无法被消除，只能被推后**。

### 2.4 可选路径与验证状态

> 可 **opt-in 改成「到顶就拒绝」**。⚠️ 遥测仅参考实现核实，**出货端未核**。

- **opt-in 模式**：库满后不再静默归并，改为**直接拒绝**新候选（语义上近似于"报没见过"，但成因是库满而非特征不像）——把不可观测的静默行为换成可观测的显式拒绝。
- ⚠️ **验证状态**：该行为只在**参考实现**里被遥测核实过，**出货端未核**——也就是交付给客户的那份代码是否真这以么做，尚未确认。

这正是本系列一贯的证据分级（参见 [神经形态芯片.md](./神经形态芯片.md) 的"软件层已验证 / 硬件验证未做"三档）：**"参考实现如此"与"出货端如此"是两件事**，必须分开说。

## 三、例外②（右下）：缓发故障的最早期

这是承认系统**理论上确实存在的盲区**。

示意图：一串红点紧贴在虚线圆**内**、幅度很小但连续偏移，标注「**一直在半径内**」。

> **小、持续、还在匹配半径内，而且变化慢到落在漂移预算之内 —— 两条都不触发。而那正是预测价值最大的阶段。**

拆开看这个"两条都不触发"：

| 判据 | 触发条件 | 本例状态 |
|---|---|---|
| 匹配半径（→ 报没见过） | 相似度低于阈值 $\tau$ | 未触发（点仍在半径内） |
| 漂移预算（→ 隔离） | 偏移速度超预算 | 未触发（变化慢，落在预算内） |
| **结果** | — | **被当作正常缓慢漂移吸收** |

而图上指出——**那正是预测价值最大的阶段**：一个正在缓慢发展、尚未表现出明显偏移的早期故障，若能在此刻被抓住，可干预窗口最长、预测价值最高。但当前判据设计（半径 + 预算）恰好会把这一类**判定为正常**。

### 这暴露的是结构性冲突，不是参数没调好

它直接呼应 [在线原型库.md](./在线原型库.md) 里的边界声明"只能跟缓慢漂移"。那一篇把这条限制列为**能力限制**；这一帧进一步指出——这条能力边界与"早期故障检出"之间存在**结构性冲突**：

> 系统为了容忍正常运行中的缓慢变化（传感器老化、季节温度、负载渐变）而设计的"跟着挪"，在数学形态上与"缓慢发展的早期故障"**是同一个现象**。二者无法靠调参数彻底分开，只能在半径/预算的松紧上做权衡。

| 调紧（半径小、预算小） | 调松（半径大、预算大） |
|---|---|
| 早期故障更容易被隔离/报出 | 正常漂移被更多吸收，误报更低 |
| 但正常漂移也被频繁报没见过，误报升高 | 但缓发早期故障更容易被"学进去"（正是客户担心的那件事） |

**这个权衡就是客户那个问题的真实答案**：不是"我们防住了"，也不是"我们没防住"，而是"我们在两个错误之间选了一个工作点"。

⚠️ **这是机制推理，不是实测**——图上明确标注。也就是说：这个盲区是从架构原理**反推**出来的理论存在，**没有**用真实缓发故障案例跑出来验证过。它的发生频率、实际严重程度都未知。讲的时候必须带上这句限定。

## 四、层2 / 层3：按听众类型分级应答

### 层2 · 对方是工程师

> 上一帧那三条限定，加一句：**预算烧完就锁死，而且可查**。「**不是我们承诺它不会，是你可以查它有没有。**」

- **"上一帧那三条限定"** 指 [在线原型库.md](./在线原型库.md) 的「预算上限 · 停学门 · 不新增类别」；
- 追加的这句是更硬的承诺：**漂移预算耗尽后系统会锁死**（停止吸收），**且这个状态是可查验的**（不是黑箱声明）。

措辞设计值得单独拎出来：

> **不是我们承诺它不会，是你可以查它有没有。**

这是从**信任声明**转向**可验证声明**：对工程师听众，"相信我们"没有说服力，"你可以自己查状态/日志"才有。与同帧"⚠️遥测仅参考，出货端未核"是同一种态度——**能给可验证的证据，就不要给承诺**。

### 层3 · 给了是加分不是减分

> 能当场说出自己边界在哪的人，比说「我们完全防住了」的人**可信得多**。**不给具体数字**；被追到那层就说「**这个我回去给您准确数字**」。

三层应答的动线：

| 层 | 触发条件 | 给什么 | 纪律 |
|---|---|---|---|
| 层1 | 默认 | 指着左图讲机制：三态分类 + "绝大多数是正确吸收，不是失职" | 不展开架构细节 |
| 层2 | 对方追问 / 是工程师 | 补"预算烧完就锁死，而且可查" | 给可验证性，不给数字 |
| 层3 | 被追到具体数字 | 承认边界 + 承诺回去给准确数字 | **不当场编数字** |

层3的道理与全系列一致（"没测过就说没测过"、"具体数字走核实流程，现场只给量级"）：**承认边界是加分项不是减分项**——现场说"我们完全防住了"的人，一旦被追问细节就会崩；而能说出自己边界在哪的人,在工程师听众眼里反而更可信。前提是**边界要真的说得清**，这也是这一帧材料存在的意义。

## 六、知识点清单

**机制层**
1. "会不会把故障学进去"可翻译成三种可判定的几何状态：**半径外**（报没见过）/ **越预算**（隔离）/ **半径内且不增长**（正确吸收）
2. **匹配半径**（→ 报没见过）与**漂移预算**（→ 隔离）是两条独立判据，可同时不触发
3. 漂移预算耗尽在几何上表现为**样本轨迹走出匹配半径且速度超限**
4. 绝大多数被吸收的样本属于第三种状态——**跟随真实漂移是正确行为，不是失职**

**架构层**
5. **两级结构**：K 槽工作记忆（短期候选缓冲）+ N 条持久库（长期原型）
6. ⚠️ **命名冲突**：本篇 K = 工作记忆槽数、N = 持久库条数；[在线原型库.md](./在线原型库.md) 的 K = 原型条数。对照时勿混
7. **N 到顶后的静默归并**：超限输入并入最近一条，**返回值同形**——外部不可观测
8. **"推后 ≠ 消除"**：加大 N 只推迟临界点，端侧资源有界，该现象无法消除
9. **opt-in「到顶就拒绝」**：把不可观测的静默行为换成可观测的显式拒绝
10. **验证分级**：参考实现已遥测核实 / **出货端未核**

**盲区层**
11. **缓发故障最早期**是理论盲区：小、慢、半径内、预算内 → 两条判据都不触发 → 被吸收为正常
12. 该阶段恰是**预测价值最大**的阶段（可干预窗口最长）
13. 这是**结构性权衡**（容忍漂移 ⇄ 检出缓发早期故障，数学形态相同），不是参数没调好
14. 松紧权衡：调紧 → 早发现但误报升；调松 → 误报低但更易"学进去"
15. ⚠️ **这是机制推理，不是实测**——盲区的实际频率与严重程度未验证

**沟通层**
16. 三层应答动线：层1 左图机制 / 层2 工程师加"可查" / 层3 被追数字时承诺回头给
17. **"不是我们承诺它不会，是你可以查它有没有"**——从信任声明转向可验证声明
18. 承认边界是**加分不是减分**；**不当场给具体数字**

## 七、待确认的空白

> [!note] 需向材料作者确认
> - 两级结构中，被"隔离"的候选是否进入 K 槽工作记忆、又经何路径转正为持久原型？原图只画了"隔离"，未交代后续流转。
> - "静默并入最近的一条"的具体后果：是**带偏那条原型的位置**，还是**丢弃候选不动原型**？两种实现的风险完全不同（前者可能慢性污染，后者只是容量受限）。
