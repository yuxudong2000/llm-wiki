# Mamba / SSM 专题：怎么用很小的状态存一整段时序

## 一、共同问题

> **同一个问题：一段很长的信号，要在设备上留下什么？**

这句话精确定义了问题的约束——不是"怎么处理长序列精度最高"，而是**部署在设备端、资源受限条件下，怎么记住历史**。这个约束直接把问题锁定在**内存/算力占用**这个维度，排除了"堆算力解决"的思路。

---

## 二、① 注意力（Transformer）——内存跟着长度涨

### 机制

> 每来一步，就把它存下来备查

自注意力的核心：处理序列时把**每个历史时间步的 Key 和 Value 向量都缓存下来**（KV 缓存/KV cache），后面每一步做注意力都要跟**全部历史**比对：

$$\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V$$

要算 $QK^\top$ 就必须保留所有历史步的 $K,V$——这就是"每来一步就存下来备查"的字面含义。

### 代价

> **内存跟着长度涨（$O(T)$ 的 KV 缓存），设备上装不下**

需要区分两个不同的复杂度：

- **计算复杂度 $O(T^2)$**：算一次完整注意力矩阵 $QK^\top$，代价是序列长度的平方；
- **KV 缓存 $O(T)$**：即使用增量推理（每步只算新 token 和历史的注意力），**存下来的 KV 依然线性增长**，序列长到几万、几十万步，缓存本身就能把设备内存占满。

对工业设备端在线监测场景是**致命的**——传感器数据持续产生，内存若随时间无限增长，几天甚至几小时设备就装不下。

### 软件说法

> **一份只增不减的日志。**

日志文件永远 append、永远不清理，磁盘/内存迟早爆满——KV 缓存正是这种性质，除非人为截断（滑动窗口、缓存压缩），但那样又丢掉更早历史。

## 三、② 状态空间模型（Mamba / SSM）——状态大小恒定

### 机制

$$h \leftarrow A\cdot h + B\cdot x$$

- $h$：**状态**，固定大小的方框；
- 每来一个新输入 $x$，状态**更新**（不是追加）：新状态 = 上一状态经矩阵 $A$ 变换，加上新输入经矩阵 $B$ 变换后的贡献；
- 输出直接从当前状态 $h$ 读出。

关键区别：

> **序列多长，状态都不变大。**

无论输入 10 步还是 10 万步，$h$ 永远是同一个固定维度向量——用矩阵运算把"历史"压缩进一个定长容器，而不是像 Transformer 那样"每一步都单独存一份"。

### Mamba 的关键改进：选择性（selectivity）

> Mamba 的加法：**让 B / C / 步长由输入决定** —— 它自己决定这一步要不要写进状态。

这是 Mamba 相对经典 SSM（如更早的 S4）的核心创新。原始 SSM 里 $A,B,C$ 是**固定的**（跟输入无关，训练完不变），没法区分"这一步输入重不重要"。

Mamba 把 $B$（输入怎么写进状态）、$C$（状态怎么读出成输出）、以及"步长"（$\Delta$，控制这一步状态更新的幅度/时间尺度）都变成**跟当前输入相关的函数**——网络动态决定"这一步信息重不重要、该不该写进状态、权重多大"。类似给状态更新装了一个"注意力式门控"，但计算代价仍是**线性**（不像自注意力要跟所有历史比对）。

对应"记住什么忘记什么"这个主题（呼应 LSTM-AE 笔记的门控机制），Mamba 不靠人为设计固定的遗忘/输入门公式，而是**让 $B/C/\Delta$ 这几个接口本身随输入自适应**，获得类似门控的灵活性，同时保持状态大小恒定、计算线性的优点。

## 四、③ 自研线：Legendre / LMU 推导版——不需要训练的压缩

全图分量最重的一格（蓝底框），呼应前一份笔记"这一格是我们自己在用的东西，要讲得比别的格更熟"。

### 机制：把一段窗口变成几个正交多项式系数

> 一段窗口 $\theta$ → $d$ 个正交多项式系数 → **还原出这段窗口**

```
一段延迟窗口的波形（长度 θ）
     ↓  投影到正交多项式基上
d 个系数（4~8 根）
     ↓  用这几个系数做线性组合，重建原函数
还原出的近似波形
```

> **$d=4\sim8$ 个系数，就能表达一整段长窗口。**

### 数学原理：正交多项式基的最优线性压缩

> 这不是学出来的 —— 是**可推导的**：正交多项式基对一段延迟窗口的最优线性压缩。**所以不需要训练。**

这句话是核心论点，跟 Mamba/Transformer 是完全不同的哲学。

**正交多项式**（如勒让德多项式 $P_0,P_1,P_2\dots$）有一个性质：任何定义在固定区间上的函数都可以**唯一地**分解成这组基函数的线性组合（类似傅里叶级数把函数分解成正弦波叠加，只是这里换成多项式）：

$$f(\theta)\approx \sum_{k=0}^{d-1} c_k\, P_k(\theta)$$

$c_k$ 是投影系数，直接由**内积**算出来（不是梯度下降学出来的）：

$$c_k = \int f(\theta)\, P_k(\theta)\, d\theta$$

**LMU（Legendre Memory Unit）**做的事：把"最近一段时间窗口的输入历史"当作 $f(\theta)$，用一组固定的（不需训练、由数学推导直接给出）微分方程/递推公式，实时维护这 $d$ 个系数，让它们始终代表"最近这段窗口的最优多项式逼近"。

**为什么低阶（4~8 个）系数就够**：正交多项式基的低阶项（$P_0,P_1,P_2\dots$）捕捉函数的**整体形状**（均值、趋势、曲率等宏观特征），高阶项才捕捉细节抖动。对"记住最近一段历史大致轮廓"这个需求，低阶几个系数足够重建出足够好的近似——跟 JPEG 压缩、傅里叶级数低频截断（保留主要信息、丢弃高频细节）是同一种压缩哲学。

### "不需要训练"的准确含义（容易误读，需精确澄清）

**这套投影系数的计算方式（数学公式、递推矩阵）本身不需要训练**——纯数学推导出的固定结构，跟输入数据、任务无关，装到任何模型里都是同一套公式。

但这**不等于整个模型不需要训练**——LMU 通常作为一个模块嵌入到更大网络里（比如接一个全连接层输出异常分数），外围权重仍需在正常数据上训练。"不需要训练"精确指**"记忆压缩这一步"免训练、由数学保证正确性**，不是说整套异常检测系统不需要任何训练数据。

这个边界控制在下面"不能这么说"红框里也间接体现——作者显然清楚这个边界，措辞上做了口径控制。

### 状态占用量级

> 状态占用是**几 KB 量级**（具体数走核，别现场给）。

内部纪律提示：具体内存占用数字要走内部核实流程再对外披露，图上先留"量级"（几 KB），细节数字不在这张图直接给出——跟"我们没测过就说没测过"是同一种诚实纪律的延续。

## 五、底部：能说 / 不能说——全图最重要的部分

两个框是全图**唯一带颜色强调**的内容（绿色可以说、红色不能说），是这份材料真正要传达给"讲这个东西的人"的**使用说明**，重要程度高于前面所有技术细节。

### 可以这么说（绿框）

> 「它把一段历史压成固定大小的状态，所以设备上能一直跑下去 —— 而且这个压缩是推导出来的，不用训练。」

把整页论证浓缩成一句对外可讲的话，两层意思：

1. **工程收益**：固定大小状态 → 内存不随时间增长 → 能在设备上长期运行（对应 Transformer 的致命缺陷）；
2. **方法论优势**：压缩方式是数学推导的、不是数据训练出来的（对应"可推导版"这个选型理由）。

这句话**没有**包含任何"比别人准/比别人好"的定量比较——这正是下面红框要专门排除的内容。

### 不能这么说（红框）——全图最关键的纪律

> ⛔ 「**比 LMU 更准**」—— 记录在案的是**打平**（非劣性），优越性检验没做过。
> ⛔ 「**在 CMAPSS 上超过 SOTA**」—— **假的**；也不要提相对 LMU 的内存优势。

**第一条**——"比 LMU 更准"不能说：

- 已做过的对比实验，结论是**打平（非劣性，non-inferiority）**——"不比 LMU 差"，不是"比 LMU 好"。这是两种不同的统计命题：**非劣性检验**只需证明"新方法不明显更差"，比**优越性检验**（证明明显更好）要求低得多；
- "优越性检验没做过"——即便直觉上或部分场景下表现不错，**没有做过严格到可以宣称"更准"的统计检验**。这是极其克制、诚实的表态，跟"我们没测过 GNN"是同一种纪律。

**第二条**——"在 CMAPSS 上超过 SOTA"是**假的**：

**CMAPSS**（Commercial Modular Aero-Propulsion System Simulation）是 NASA 发布的航空发动机退化仿真数据集，是**剩余寿命预测（RUL, Remaining Useful Life）领域最常用的公开基准测试集**之一。图里明确标注这个说法**假的**——意味着可能已经流传过"我们在 CMAPSS 上超过 SOTA"的不实说法，作者专门辟谣纠正。这是一个罕见但重要的信号：**材料作者在主动纠正夸大宣传，而非助推它**。

**第三条隐含禁令**——"也不要提相对 LMU 的内存优势"：

有点反直觉——按理说若自研线相对 LMU 有内存优势，应是个卖点。合理推测：这类内存对比可能**同样没经过严格、可复现的实测验证**，或对比条件（部署环境、模型配置）不完全对等，所以选择**保守**，不主动声称这项优势，避免日后被追问细节答不上来或被证明不严谨。

### 这两块框揭示的方法论

展现出一种在技术传播/客户沟通场景下相当罕见的严谨性——**把"已验证的"和"想让人相信的"严格分开**。可总结成一条通用原则：

> **凡是要对外讲的技术优势，都必须能追溯到具体做过的实验和它实际证明的命题（哪怕只是"打平"这种不那么亮眼的结论），不能用"听起来应该更好"去填补"没有做过的测试"这个空白。**

这跟整套材料贯穿的态度一致——从"我们没测过 GNN，回去补"，到这里"打平不是更准，CMAPSS 超 SOTA 是假的"，都是同一种**诚实优先于说服力**的纪律。

## 六、三格对照：解决同一个问题的三种哲学

| | Transformer | Mamba/SSM | LMU（自研线） |
|---|---|---|---|
| **状态大小** | 随时间线性增长 $O(T)$ | 固定 | 固定（几 KB 级极小值） |
| **压缩方式** | 不压缩，全部存下来 | 学出来的（$A,B,C$ 训练得到；Mamba 让 $B/C/\Delta$ 依赖输入） | **推导出来的**（正交多项式基，数学保证，免训练） |
| **能否解释"为什么记得住"** | 不需要解释，直接查历史 | 弱（黑箱学出的矩阵） | **强**（正交基的最优线性逼近，有明确数学意义） |
| **能否部署在资源受限设备上长期运行** | 不能（内存迟早耗尽） | 能 | 能 |
| **已验证的优势边界** | — | — | 仅"打平"（非劣性），非"更准" |

三者共同要回答的问题都是"一段很长的信号，要在设备上留下什么"，区别在**压缩历史信息的方式**：Transformer 选择不压缩（代价是资源爆炸）；Mamba/SSM 选择**学一个压缩函数**（代价是黑箱、可解释性弱）；LMU 选择**用数学直接推导出最优压缩公式**（代价是压缩方式本身固定、不能像深度网络那样"随数据调整到极致"，所以只能打平、暂时无法证明碾压）。

## 七、知识点清单

1. **KV 缓存（KV cache）**：Transformer 自注意力推理时缓存历史 Key/Value，占用随序列长度线性增长 $O(T)$，区别于计算复杂度 $O(T^2)$
2. **状态空间模型（SSM）**：线性状态递推 $h\leftarrow Ah+Bx$，状态大小与序列长度无关
3. **Mamba 的选择性（selectivity）**：让 $B/C/\Delta$（步长）由输入决定，赋予类似门控的动态记忆能力，同时保持计算线性
4. **正交多项式基**：勒让德多项式等，函数可唯一分解为基函数线性组合，系数由内积直接算出（非训练）
5. **LMU（Legendre Memory Unit）**：用正交基对延迟窗口做最优线性压缩，$d=4\sim8$ 系数即可表达长窗口，压缩公式本身免训练
6. **"不需要训练"的精确范围**：记忆压缩这一步免训练 ≠ 整个模型（含外围权重）不需要训练数据
7. **非劣性检验 vs 优越性检验**：统计学上两种不同强度的命题，"打平"只对应前者
8. **CMAPSS 数据集**：NASA 航空发动机退化仿真数据集，RUL 预测领域常用公开基准
9. **对外表述的事实核查纪律**：已验证的结论与想传达的印象严格分离，不用"听起来应该更好"填补未测试的空白
