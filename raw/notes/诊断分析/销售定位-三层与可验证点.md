# 销售定位：我们卖的是哪一层

> 来源：一张销售定位表示意图（原始图片未归档，仅整理文字内容）
> 整理时间：2026-09-23

> [!warning] 保密标记
> 与前几帧同属一份内部材料（D1 系列，承 [噪音问题-环境还是传感器.md](./噪音问题-环境还是传感器.md)，接 [价值论证-三个问题用他自己的数.md](./价值论证-三个问题用他自己的数.md)）。含内部销售策略与竞品定位表述。**本仓库会 push 到 git remote**，入库前需确认可达范围或做去标识化处理。

**一句话**：这一帧是**销售定位表**——把产品价值拆成三层（适应 / 运维 / 形态），**每一层都配一句客户听得懂的话，外加一个"客户自己能验证"的依据**。

**副标题（全帧方法论）**：

> 能被对方**自己验证**的话才有说服力。**他验证不了的，说了等于没说。**

这句话把前几帧反复出现的"可验证性"从**技术承诺**（[应答设计-故障会不会被学进去.md](./应答设计-故障会不会被学进去.md) 的"不是我们承诺它不会，是你可以查它有没有"）提升成了**销售原则**——不是"我们说话要诚实"，而是"**只有他自己能查证的话，才值得说出口**"。

---

## 一、三层 × 能听懂的话 × 他能验证什么

| 层 | 客户听得懂的话 | 他自己能验证什么 |
|---|---|---|
| **① 适应** | 「不用先给我们采几个月数据，也不用每换一次季节就叫人回来重训一遍。」 | **他知道上一次重训花了多久、找了谁** |
| **② 运维** | 「传感器坏了、通道停更了，我们会告诉你是传感器的问题，不是设备的问题。」 | **他一定被误报坑过** |
| **③ 形态** | 「算在现场，数据不必出厂。」 | **数据出厂在国企 / 涉密场景常常直接决定行不行** |

结构上，左列是**我们说的话**，右列是**为什么这句话对他有效**——右列全部不是"技术指标"，而是**客户自己已有的经验、记忆、约束**。

### 层① 适应

对应前面所有关于"不用重训 / 在线自适应"的论证（[在线原型库.md](./在线原型库.md)、[应答设计-故障会不会被学进去.md](./应答设计-故障会不会被学进去.md)）。

可验证点是——**客户自己清楚上一次重训的代价**（花了多久、找了谁、沟通成本）。我们不必证明"我们能省多少"，只需**唤起**他自己已经付过的那笔账。

### 层② 运维

直接是 [噪音问题-环境还是传感器.md](./噪音问题-环境还是传感器.md) 那句「我们区分『传感器坏了』和『设备坏了』」的销售版。

可验证点更妙——「**他一定被误报坑过**」：这不是需要论证的命题，是**几乎必然成立的处境**。用客户的**既有痛点**作为验证基础。

### 层③ 形态

「算在现场，数据不必出厂」——验证方式与前两条不同，是**制度性约束**：在国企、涉密场景，数据能否出厂往往是**一票否决**级别的要求，**不需要比较优劣**。

### 层③ 的关键澄清：两种形态别混

> **两种形态别混**：
> - **结构监测 / 多路汇聚** → **现场一台边缘计算盒**（带 NPU 的那类）
> - **单台设备贴装** → **设备里一块小板**（MCU 级）

这是全表**唯一的硬技术信息**，直接呼应 [神经形态芯片.md](./神经形态芯片.md) 那句「现在交付的产品跑**普通 MCU 和网关**」：

| 形态 | 场景 | 硬件 | 算力档 |
|---|---|---|---|
| 边缘盒 | 结构监测（桥 / 隧 / 边坡）、多路汇聚 | 带 NPU 的计算盒 | 高（有加速器） |
| 小板 | 单台设备贴装 | **MCU 级** | 低（单片机） |

两档算力差着数量级，**能跑的东西不同**——这也顺带解释了为什么讨论"能不能上神经形态芯片"时，答案取决于形态。

## 二、底部蓝框：② 被低估

> 客户嘴上问**精度**，钱**实际花在「误报太多，最后没人看了」上**。而「**先查采集还活着没有**」这件事，**竞品路线没有对应的模块** —— **不是做得差，是根本没有这一块**。所以在客户面前，**第一个问「这些点位的数据最近还在更新吗」的人，会被当成内行**。

三层递进：

1. **指出真实痛点与表面需求的错位**——嘴上问精度（技术指标），钱花在"误报太多没人看"（**运维现实**）。同构于 [价值论证-三个问题用他自己的数.md](./价值论证-三个问题用他自己的数.md) 的"误报率不是技术指标，是人工工时"。
2. **"不是做得差，是根本没有这一块"**——措辞纪律的延续：区分**能力差距**（谁好谁坏，可争）与**结构缺失**（有没有，不可争）。说"竞品做得差"会立刻引发争论；说"竞品根本没有这个模块"是**可查证的事实陈述**。
3. **"第一个问『数据最近还在更新吗』的人，会被当成内行"**——把上一帧那个具体判别动作（看单调量）转化为**社交收益**：谁先问出这个问题，谁就在客户眼里建立了专业形象。

## 四、知识点清单

1. **销售原则：只说他能自己验证的话**——"他验证不了的，说了等于没说"
2. 三层定位：**① 适应**（不用长期采数 / 不用季节重训，"他知道上次重训花了多久"）、**② 运维**（区分传感器与设备，"他一定被误报坑过"）、**③ 形态**（数据不必出厂，涉密场景一票否决）
3. 右列（可验证依据）全部是**客户的既有经验 / 记忆 / 制度约束**，不是技术指标
4. **两种交付形态别混**：结构监测 / 多路汇聚 → 带 NPU 边缘计算盒；单台设备贴装 → MCU 级小板
5. **② 被低估**：客户嘴上问精度，钱花在误报上；"先查采集是否还活着"是竞品的**结构性缺失**，不是能力差距
6. **能力差距（可争）vs 结构缺失（不可争）**——后者的表述更安全也更锋利
7. **"第一个问『数据最近还在更新吗』的人会被当成内行"**——技术动作 → 社交收益
8. ⚠️ **证据不得跨档**：小板档实测不能支持边缘盒档说法；边缘盒选型与报价未定
